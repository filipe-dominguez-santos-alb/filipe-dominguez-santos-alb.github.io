# ~/notes

A hacker-style blog for GitHub Pages with an Obsidian-style graph view. Plain Jekyll, no plugins to install, no build step on your machine.

- Every file in `_posts/` becomes a page, a line on the home list, an RSS entry and a node in the graph.
- A small graph sits in the sidebar of every page. The full interactive graph lives at `/graph/`.
- The graph data is generated at build time from your posts' tags and `related` links.

## Structure

```
_config.yml          site title, description, baseurl, permalinks
_layouts/
  default.html       page shell: header, sidebar graph, footer
  post.html          single post layout
_posts/              your blog posts (one markdown file each)
assets/
  style.css          all styling and colour variables
  graph.js           graph engine (sidebar and full page)
graph/index.html     the full-screen graph page
graph.json           graph data, generated by Jekyll from _posts
index.html           home page and post list
```

## Publish

1. Push the contents of this folder to the root of a GitHub repo.
   For a personal site, name the repo `<username>.github.io`.
2. In the repo, open Settings, then Pages, and choose "Deploy from a branch" on your main branch, root folder.
3. If the repo is not `<username>.github.io`, set `baseurl: "/repo-name"` in `_config.yml`.
4. Wait a minute or two. The site appears at `https://<username>.github.io/`.

## Write a post

Create `_posts/YYYY-MM-DD-my-title.md`:

```
---
layout: post
title: My title
tags: [linux, security]
related: [ssh-tricks]
---
Your text in markdown.
```

- The date comes from the filename. Posts dated in the future are hidden until that day.
- `tags` become tag nodes in the graph. Posts that share a tag end up close together.
- `related` lists the slugs of other posts to link to. The slug is the filename without the date and extension, so `2026-10-19-ssh-tricks.md` has the slug `ssh-tricks`.
- Commit and push. The post appears on the home page, in the feed and in the graph.

## Pagination

The home page shows 10 posts per page, with newer/older links at the bottom (`/page2/`, `/page3/`, and so on). Change `paginate` in `_config.yml` to show more or fewer. Pagination only works on the root `index.html`, so keep that file as `.html`.

## Photos

Put images in `assets/images/` and give a post a thumbnail for the home page:

```
---
layout: post
title: My title
image: /assets/images/my-photo.jpg
---
```

Posts without `image` get a small `>_` placeholder. Inside a post, add a photo with `![description]({{ '/assets/images/my-photo.jpg' | relative_url }})`. Keep files under about 500 KB.

## Projects

The `/projects/` page shows a grid of cards, three per row (two on tablets, one on phones), with the photo on top and the title below. Edit `_data/projects.yml`:

```
- title: My project
  url: https://github.com/you/my-project
  image: /assets/images/projects/my-project.jpg
```

Add one entry per project. Without `image`, a `>_` placeholder shows.

## Customise

| What | Where |
| --- | --- |
| Name and intro text | `index.html` |
| Site title and description | `_config.yml` |
| Colours (background, text, accent, node colours) | variables at the top of `assets/style.css` |
| Font | the Google Fonts link in `_layouts/default.html` and `--mono` in `style.css` |
| Graph physics (spacing, repulsion) | `tick()` in `assets/graph.js` |
| Header links | `<nav>` in `_layouts/default.html` |

## Preview locally (optional)

You need Ruby and Bundler. Create a `Gemfile` next to `_config.yml`:

```
source "https://rubygems.org"
gem "github-pages", group: :jekyll_plugins
```

Then run:

```
bundle install
bundle exec jekyll serve
```

Open http://localhost:4000. If you set a `baseurl`, add it to the address.

## Troubleshooting

- **Graph is empty or does not load:** open the browser console. A 404 on `graph.json` usually means `baseurl` is wrong.
- **Styles missing on a project repo:** set `baseurl` as described above.
- **A new post does not show up:** check the filename starts with a valid date and ends in `.md`, and that the front matter starts and ends with `---`.
- **A `related` link does nothing:** the slug must match an existing post exactly. Unknown slugs are ignored.
- **Build errors:** the Actions tab in your repo shows the Jekyll error message.

## Notes

- The graph does not read `[[wikilinks]]` from post text. It only uses tags and `related`.
- The graph is drawn on a canvas with no external libraries. Only the font is loaded from Google Fonts.
